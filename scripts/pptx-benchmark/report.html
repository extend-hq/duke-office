Confirmed gaps and interpretation

  • The current parser rejects zero-slide presentations, although the presentation schema permits an absent slide list.
  • Classic chart extraction misses 3D chart families and secondary plots in combination charts. Shared SVG rendering and source XML retention do not fill the missing structured series.
  • Notes flatten all text into a single string and include notes-page metadata; they do not retain rich text or a clean notes-body boundary.
  • The Rust model has no media node, shape action, alt-text or hidden-object fields, even though the React model already provides several of these fields.
  • Animation/timing, transitions, embedded-object metadata, math, ink, sections and presentation-level settings need explicit coverage and downstream contracts.

Raw source-literal F1 is retained. It should not be interpreted as hallucination precision: the reference deliberately omits inherited master/layout content, SmartArt caches and chart labels from its body-text scope. Conversely, 100% recall on this scope does not establish full-format or display accuracy.

Method and reproduction

Release native builds use opt-level 3, thin LTO and one codegen unit. Each document has one cold parse followed by five warm samples averaging 1–10 parses. Inputs and engine order are randomized with a saved seed. File reads, process startup, imports, output serialization, output hashing and reference generation are outside warm timing. Rust-pptx includes shared artwork/SVG generation. Office Oxide includes its IR projection. Python-pptx includes eager traversal of its lazy model. MarkItDown uses its dedicated PPTX converter, without OCR or LLM calls. Python garbage collection can occur during timed work; explicit result destruction is outside each timer. Timing jobs ran sequentially on a shared development machine.

The reference uses Python ElementTree and ZIP independently of the tested parsers. It checks literal slide paragraphs and tables in source drawing-tree order, explicit formatting, note-body text, picture relationships/payloads, classic chart caches and explicit shape frames. The first AlternateContent choice is selected. It is not an Office implementation and does not resolve complete style inheritance, advanced extension semantics, generated content or render layout.

Raw samples, compact native outputs, byte hashes, source URLs, pinned commits, dependency locks and the scorer are retained beside this report. The corpus manifest permits exact reproduction. No hosted commercial services were benchmarked; no documents were uploaded to a third-party parsing API.
