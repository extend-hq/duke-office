# Office picture rendering coverage

`duke-office-art` is shared by `duke-docx` and `duke-docx-wasm`. The parser resolves relationships and theme colors, preserves original assets and ordered presentation properties, and passes picture appearance to the shared renderer. The viewer consumes the resulting image and paint bounds; `presentation.transformApplied` prevents applying a second rotation or flip.

This is a measured implementation, not full OfficeArt or pixel-identical Word compatibility. Parsing a property, rendering it, preserving a stored preview, and proving visual equivalence are separate capabilities.

| Feature family | Current behavior | Remaining limitation |
| --- | --- | --- |
| Embedded, linked and SVG alternative images | Resolve available assets and retain source relationships | Missing SVG alternatives recover a raster asset; Word can display an error instead |
| Source crop and stretch destination | Signed and percentage rectangles | Invalid or inverted rectangles use preserved fallback |
| Raster tiling | Embedded PNG/JPEG-JFIF/BMP resolution and 72 DPI fallback for missing resolution, including GIF; tested XML DPI settings do not override tile size | TIFF/WebP intrinsic tile resolution is not implemented; high-resolution tile sampling/alignment still differs |
| Rotation, flips and grouped transforms | Shared SVG and separate paint bounds; nested frame scaling followed by local rotation | Text and effects in arbitrary transformed groups need broader comparison |
| Geometry and connectors | 187 preset definitions, bounded custom guides and multiple paths, polar arcs, markers, local transforms and separate paint bounds | Native visual parity is not established for the full preset atlas |
| Shape fills | 54 native pattern tiles, scaled linear and circular gradients, rectangular path gradients, and supported bitmap fills | Pattern page phase requires mounted placement; rotated/grouped phase and nonrectangular shape-contour gradients need broader support and comparison |
| SmartArt | Shared semantic graph and saved drawing reader; DOCX and PPTX use shared shape/picture paint and retain explicit saved text transforms | Full data-to-layout generation is not implemented; missing drawings or incomplete text transforms use warned fallback; native text-transform parity is unmeasured |
| WordArt text | Shape portable glyph outlines; render preset warp guides, measured text fitting, no-fill/solid/gradient text paint, typed outlines and identity-scale outer shadows | Native comparisons retain font substitution and rasterization differences; transformed shadows and non-solid/compound text outlines retain fallback |
| Color and alpha | Grayscale, bilevel, luminance, duotone, HSL, tint, color replacement and alpha operations | Software/hardware precision and color-space propagation can differ |
| Borders and ordinary effects | Shared normal/system dash presets, round default joins, outward-offset rectangular picture borders, closed compound shape outlines, shadows, glow, soft edges and reflection | Nonrectangular picture border offsets remain approximate; open compound outlines, compound endpoint markers, preset shadows and several effect parameters remain limited |
| Artistic picture extensions | Display the processed bitmap and preserve original image/effect settings | Regenerating artistic effects from the original is not implemented |
| Effect graphs and 3D | Bounded sequential effect containers, five blend modes, alpha modulation and selected color operations; preserve source properties on fallback | Referenced effects, multiple sibling branches and geometry-expanding graph nodes retain fallback; 3D paths support projection, bevels, extrusion and material lighting with measurable native shading differences |
| Raster normalization | Bounded PNG, JPEG, GIF, BMP, TIFF and WebP decoding where needed | First frame only; no complete PICT, JPEG XR, EPS, WMF or EMF rendering coverage |
| Legacy VML pictures | Crop, rotation/flips, opacity, grayscale and bilevel | Gain, black level, gamma and chromakey remain preserved with warnings |
| Export | Retain unchanged source appearance and relationships through reconstruction | Editing arbitrary effects is outside this renderer API |

Microsoft specifies that an embedded picture with artistic image properties can contain the processed bitmap in the main blip and the original JPEG XR image in the extension layer. Displaying that saved bitmap avoids applying effects twice. Linked and metafile blips have different rules. [MS-ODRAWXML, Pictures](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/f10da8b6-40f3-4527-9c3d-9f5c2e9cff45).

## Native evidence

The [November 6 expanded comparison](office-art-comparisons.md) adds 30 isolated native Word pairs covering SmartArt, WordArt, 3D model previews and emoji, projected 3D shapes, icons, reconstructed InkML and an artistic-cache control. It exercises glyph-outline deformation, font fitting, material lighting and pressure-aware ink. Saved previews and cached artistic bitmaps are explicitly distinguished from regenerated rendering.

The local investigation used Word for Mac 16.106.1, build 16.106.26021521, its OfficeArt and Gfx frameworks, REA function analysis, and native Word screen/PDF output. The inventory found 51 OfficeArt model classes, 65 GEL effect interfaces, 17 blip effect choices and 27 extension tokens. These overlapping inventories are evidence of code presence, not counts of independently supported features.

Targeted function analysis established luminance coefficients, grayscale weights, the 240-step HLS conversion, native HSL parameter mapping, shortest-arc tint interpolation, and alpha/color processing. Order-sensitive native captures confirmed preprocessing of threshold and color-key operations before the remaining blip effects. The main Word executable analysis timed out; the smaller rendering frameworks provided the relevant function evidence. Proprietary binary slices and decompiler output are retained locally and are not distributed with the crate.

Native Excel 16.107.3 PDF operators distinguish normal dot `[1,3]`, dash `[4,3]`, and dash-dot `[4,3,1,3]` from system patterns, in units of declared line width. Word's dashed-border output independently confirms `[4,3]`. Rectangular picture borders follow a centerline offset outward by half the declared width. Shared rendering now follows those paths and spacing; export-specific stroke quantization is not fitted to one capture.

The 54 pattern tile images recovered from native Word PDF output are reproduced exactly at their native eight-point period. This proves tile content and scale, not complete page rendering or transformed pattern phase. Native PDF operators also establish inverse-aspect direction for scaled linear gradients, a true circular radius for the centered radial control, and outside-to-inside band ratios for the four closed compound outline styles. Shape SVG paint canvases round outward to integer bounds while retaining the original layout size.

A bounded multiply/color-replacement effect-tree control has 0.57% mean absolute RGB error after the native effect raster is composited and resized to the browser image dimensions. This is a color-rendering check, not page-position parity or a score for all effect graphs. Another control preserves gradient-stop alpha in SVG while native PDF export omits it; that discrepancy needs an on-screen Word reference before changing shared alpha semantics.

REA analysis of Word's Gfx framework shows 72 DPI components in `GetDesktopVirtualDPI`, with backing scale stored separately. Twelve native Word tile controls agree with Excel's PNG, JPEG and GIF calibration: missing resolution uses 72 DPI, embedded 96/144 DPI changes physical tile size, and the tested `blipFill/@dpi` and `a14:useLocalDpi` settings do not change that size. Word resamples the image in two controls while retaining the same physical tile size. These controls establish tile dimensions, not complete frame or pixel equivalence, and do not establish behavior on untested Office versions or platforms.

## Reproduction and interpretation

The scripts in `scripts/image-fidelity` generate a deterministic 40-case picture matrix, capture the installed Word output and compare fixed page regions with browser screenshots. Each picture has a fixed layout frame and each comparison includes overflow. Source and reference hashes prevent substituting changed inputs. Blank and missing cases remain in the report denominator.

Run the native `image_fidelity` example to extract the model and optionally export a reconstructed document. `prepare-pages.py` builds fixed pages from native output. `prepare-capture.py` generates a Playwright CLI capture function for either those pages or the React DOCX playground. The comparison reports ink overlap and RGB agreement within 16 levels over the union of ink. White margins do not inflate color agreement. The plain picture establishes raster-sampling differences between Word's PDF output and the browser.

The native matrix includes a blip blur that is blank in both Word's UI and PDF export; the SVG renderer draws it. This remains an explicit divergence. The missing-SVG-alternative case also differs intentionally because the parser recovers an available raster image. Neither case is counted as equivalent. A separate 10-case native matrix checks effect ordering and omitted HSL parameters. These bounded matrices do not cover every codec, shape preset, effect combination, Office version or platform.

A separate five-case native comparison covers root and nested group rotation, reflection, and nonuniform resizing with a rotated child picture. Word scales each child frame before applying its local rotation; the renderer follows this ordering to avoid shear. All five cases achieve at least 97.92% ink overlap, with mean absolute channel error between 0.13 and 0.66 on the 0–255 scale. Reconstructing and reparsing their paragraphs preserves all five rendered sources, paint bounds, presentation properties, and anchors exactly.

On November 5, 2026, the 40-case React DOCX capture using the workspace DOCX/WASM 0.2.9 candidate had **100.00% median RGB agreement within 16 levels** against the same Word PDF rasterized with Cairo. **37/40 cases reached 96% color agreement**; the all-case mean was **94.11%**. Soft edges, the blank native blur, and missing-SVG-alternative recovery remain divergences. No cases are excluded. [All per-case measurements](readme-assets/word-picture-comparison.csv) · [Capture provenance](readme-assets/word-picture-provenance.json). The provenance records the actual served WASM and viewer source hashes. This is a workspace visual measurement and does not establish registry availability or a feature-support percentage.

The same browser candidate reaches 96% color agreement in **4/5 group cases** (98.55% median, 97.67% mean) and **10/16 shape/connector cases** (97.51% median, 93.78% mean). Thin-stroke sampling, custom formula geometry and several connector cases remain below target. All 61 cases retain the original input bytes, native PDF and fixed comparison region. [Group measurements](readme-assets/word-group-comparison.csv) · [Shape measurements](readme-assets/word-shape-comparison.csv) · [Group provenance](readme-assets/word-group-provenance.json) · [Shape provenance](readme-assets/word-shape-provenance.json).

The final workspace capture also measures all **123 drawings from two complete supplied documents** with successful native references. Their **50.00% mean** and **50.84% median** fixed-coordinate color agreement, with **0/123 reaching 96%**, include document layout differences. Native and viewer art regions are not independently aligned. The first rows already differ by about 2–3 pixels vertically, with accumulated table-row drift; pattern sampling, gradient alpha and unsupported effects add rendering differences. The other two supplied inputs contain **206 drawings without successful native references**; derived opening probes are not substituted into this denominator. [All 123 measurements](readme-assets/word-art-document-comparison.csv) · [Provenance](readme-assets/word-art-document-provenance.json). A separate two-page mixed-visual document reaches 89.09% and 91.89% full-page color agreement after inline-baseline corrections, retaining all 18 visuals; it also remains below target.

Both original Splash references and Cairo references are retained with the same input and native PDF hashes. Splash resamples the unchanged bitmap into one extra pixel; Cairo reproduces that control exactly. The current picture capture has 94.75% median color agreement against Splash. [Picture](readme-assets/word-picture-comparison-splash.csv), [group](readme-assets/word-group-comparison-splash.csv) and [shape](readme-assets/word-shape-comparison-splash.csv) Splash ledgers retain all cases. The comparison region and scoring rules are identical across rasterizers.

Native soft-edge masking uses byte-quantized box passes before a Gaussian blur. Its effective inset depends on the effect raster resolution. The SVG implementation preserves the binary alpha mask and uses the measured Gaussian radius mapping, but does not reproduce all device-resolution quantization. Outer shadows use the measured radius-to-deviation mapping and reach 100% color agreement in the bounded shadow case.

The expanded shape/connector engine decodes all 187 presets in the bounded browser smoke matrix. The PPTX atlas paints 284 of 299 cases through shared SVG, with 15 explicitly warned fallbacks. These are implementation and decoding checks, not new native visual scores. See [shared architecture](office-art-architecture.md) and the [manual fixture atlas](readme-assets/office-art-manual-atlas.zip).

The separate 48-case Excel replay retains all original reference crops and uses their original browser placement. Mean absolute RGB difference, divided by 255, decreased from 7.32% to 2.36% across all 48 cases. The 12 border calibration cases decreased from 5.10% to 1.61%; the 12 tile calibration cases decreased from 18.90% to 5.19%. This crop-based error measure differs from the Word ink-region agreement metric above. The 144 DPI PNG case still has 12.55% RGB difference despite matching native physical tile size, and other sampling/alignment differences remain. No reference or case was removed to improve these measurements.
