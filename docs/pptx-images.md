# Image representations and fallbacks

An image node's `assetId` identifies the selected representation. When an embedded SVG extension is selected and the main DrawingML blip resolves to a distinct retained asset, `fallbackAssetId` identifies that saved representation. The optional field is omitted when no distinct available fallback is known. Both IDs address the presentation's asset map; they describe one picture occurrence, not two pictures.

This follows [MS-ODRAWXML §1.3.3](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/7e1f1524-1569-4aa2-a6c9-aab2d855bd48): the SVG extension identifies the vector resource while the main blip holds its rasterized compatibility representation. [CT_SVGBlip](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/68e0150d-6a01-4ba5-ac4d-5a18d685229b) defines embedded and linked relationships. The parser currently selects retained embedded SVG resources; external SVG resources are not downloaded.

Picture fill inheritance resolves the selected and fallback assets together against the relationship map of the same slide, layout, or master. Cropping, opacity, effects and geometry continue to belong to the picture. Media posters use the same image contract. Legacy images, ink previews, 3D previews and control previews do not infer a fallback merely because another asset exists in the package.

The React viewer's direct-image path tries the selected asset first and then the associated fallback when the asset or its data is missing, URL resolution fails, or image decoding fails. It retains the same crop and effects, attempts each representation at most once, and reports an error only if neither representation can be used. A stale render generation cannot apply the fallback or deliver a late error. Consumers without support for the optional field continue to use `assetId`.

SVG selection requires the [qualified `svgBlip` element](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/2451f45e-5d77-4661-86d1-0a017fced779), a qualified embedded relationship attribute and the DrawingML `blip/extLst/ext` container path. Alternate prefixes and default element namespaces are supported. Foreign elements, foreign or unqualified relationship attributes, and foreign extension containers cannot select a replacement. If an earlier entry has no available embedded payload, later eligible entries are considered. The selected asset and original compatibility asset still resolve together against the same owning part.

Generated `pictureSvg` artwork has a separate rendering path. When a saved compatibility asset is available and the picture needs generated artwork, the parser also emits optional `fallbackPicture: { svg, paintBounds? }`. The compatibility picture is rendered with the same inherited fill, crop, geometry, transform, colors and effects. Its own bounds must be used when selected; replacing an embedded URL in the preferred SVG would not preserve tiling or native raster effects. Absent bounds are omitted consistently by native and WASM serialization. A fallback can be available even when the preferred representation cannot be rendered.

The React viewer tries the preferred generated artwork, then the generated compatibility artwork. An outer SVG can decode successfully while its embedded image is blank, so this path validates nested SVG `image` and `feImage` resources before choosing it. It accepts self-contained data resources, follows nested SVGs up to depth 32, respects UTF-16 and declared XML encodings while inspecting them, and limits explicit browser image decodes to four at a time per presentation cache. The browser must still be able to decode each original resource. External resources are not fetched. The resource scan includes unused definitions, so an unusable resource there can conservatively cause fallback. Fragment references are left to the browser; CSS resource URLs are outside this validation. These checks establish decode availability, not pixel fidelity to PowerPoint.

In-flight work is deduplicated for identical artwork. Mount readiness includes both attempts, and disposed mounts or stale render generations cannot write a late image or report a late error. Paint bounds are applied only after a representation succeeds, with transforms already baked into generated artwork applied once. Consumers without this optional field continue to use the original selected artwork or asset.

Nested data URLs are decoded locally rather than passed through `fetch`, so resource inspection does not require permission from CSP `connect-src`. The complete 30-model and eight-runtime browser checks pass with `connect-src 'none'`. Four additional pixel checks cover base64 fragments, escaped base64, percent-encoded UTF-16 and Unicode data URLs under the same policy. The browser still needs permission to display images under its image-loading policy.

The established comparative image metric continues to score the selected payload against each source main-blip occurrence. Its historical 113 SVG/raster mismatches are not silently reclassified as successes. The association audit independently verifies that each emitted fallback belongs to the same source picture or inherited placeholder and that both payloads exactly match the package. These checks measure preservation, not rendered equivalence.
