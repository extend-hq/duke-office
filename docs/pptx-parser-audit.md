## Object and media iteration

The next local iteration adds typed common-object metadata, shape click/hover actions, explicit source ownership, audio/video nodes, OLE payloads, poster associations and media trim/fade/bookmark data. Relationship parsing now preserves `TargetMode=External` and decodes XML attribute entities. Internal media payloads resolve by relationship even outside conventional media directories; the parser does not fetch external targets. Media extension `r:link` takes precedence over `r:embed`, as specified by [MS-PPTX CT_Media](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/f8b7e1cb-976e-4f38-8139-f9e5ffa826e8). Time offsets are normalized to milliseconds according to [ST_UniversalTimeOffset](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/a3ead080-d9cb-4b4a-8014-6d815248c23b); trim-end means duration removed from the end.

The independent XML audit passes all 318 inputs against the preceding notes/chart build. It validates 15,074 rendered/master/layout object representations, including 352 explicit descriptions, 341 nonempty alt-text values, one accessibility title, four explicit hidden flags, 136 click actions and 131 resolved object hyperlinks. It checks 56 OLE nodes and three audio/video nodes, with 58 available referenced payloads matching their exact package bytes and 29 newly retained assets. These counts include inherited duplicates; they are not a unique-source-object denominator. No hover/decorative source occurrence was scored in this corpus. Unsupported-graphic warnings for newly recognized OLE nodes are deliberately outside the previous-warning comparison.

Existing poster artwork is preserved, including pictures inside markup-compatibility fallback branches. In 26 inherited representations, the wrapper retains the original prefixed identity while its nested poster uses a local identity; the audit explicitly checks this relationship before comparing the complete poster. Synthetic package probes independently exercise escaped and external relative URLs, media link/embed precedence, nonstandard payload paths and multiple supported time-unit conversions. All six probe checks pass. CD-audio track semantics and VML-only OLE previews remain incomplete.

React's model now matches the emitted fields. The local viewer respects hidden/alt-text metadata, resolves internal slide links, displays media posters before user-initiated playback, and exposes embedded objects as downloads rather than treating them as video. Trim bounds are applied through browser media events; this is not sample-accurate editing. Hover behavior, action sounds, fade playback and bookmark UI remain unimplemented, although their parsed metadata is retained. A browser interaction probe confirms loaded posters, decoded video, download links, hidden objects and navigation; it does not establish native PowerPoint pixel fidelity. All 392 existing Rust checks, 41 existing viewer checks and model/viewer typechecks pass. Existing assertions were adapted to the new media representation; no unit tests were added.

A separate speed-only change stores short XML names/attributes with [CompactString](https://docs.rs/compact_str/0.10.0/compact_str/) and boxes optional object metadata/actions. Full serialized outputs and failure statuses remain exactly equal on all 318 files. An interleaved 30-input tuning sample measured a 1.076× median paired speedup over the uncompressed object-model build (95% bootstrap interval 1.025–1.124×); the sum of per-input medians improved only 0.5%, so large-document work remains dominant. It beat Office Oxide on 8/30 of those inputs. This tuning sample is not a new untouched holdout, and its ratio must not be multiplied by previous iteration ratios.

## Equations, ink and embedded controls

Content-part ink resolves its relationship payload, reuses the bounded Office ink decoder, and exposes physical coordinates, pressure/contact state, brush properties and trace order. The slide transform and decoded trace-center bounds produce SVG artwork with stroke overflow, including zero-extent dots. The source InkML remains intact, including recognition annotations. [MS-PPTX xfrm](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/5ec5c216-2cbb-417a-b7b7-b367b1ec06c2) defines the content-part transform. Unsupported InkML transforms keep a saved compatibility preview when present. Uncommon transforms, continuation semantics, full pen behavior and native pixel fidelity remain open.

Embedded controls are discovered outside the ordinary shape tree. They expose class ID, persistence, property entries, original definition and binary payload references. Saved VML previews are matched by shape ID, with physical-unit geometry and relationship-backed images. Child DrawingML previews take precedence. React displays the static preview and exposes the payload; it does not execute ActiveX. Nested VML groups and full control-specific semantics remain incomplete. See the [PresentationML control definition](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.control?view=openxml-3.0.1).

All 12 focused package checks pass, covering math namespace/default/fallback behavior, ink differential coordinates and zero extents, and control payload/preview relationships. All 392 existing Rust checks and 41 existing viewer checks pass; model and viewer typechecks pass. The actual WASM bridge agrees with native acceptance on 318/318 inputs and with all 278 successful compact semantic models and payload hashes. The existing 21 shape-SVG length differences remain; full SVG equality is not claimed. LibreOffice omits these ink marks and has different font/layout output, so its PDF is an inspection aid rather than an ink or native PowerPoint pixel oracle.

## Current pipeline

The parser detects ZIP or compound-binary bytes, checks configured limits, resolves presentation and slide relationships, loads reusable layout/master/theme parts, builds XML trees and inheritance contexts, then creates slide nodes and assets. Shared OfficeArt and chart engines generate SVG during the production parse. Masters and layouts also receive public model nodes. WASM serializes this model for React.

The original implementation repeatedly deep-cloned layout, master and theme trees for each slide. The local changes borrow them. It still reconstructs shape appearance XML before passing it to shared artwork parsers, but reduces temporary allocations and repeated scans. The benchmark preserves the original full-model baseline independently of semantic improvements.

## Remaining package and comment contracts

Source inspection confirms that the presentation entry point is hardcoded to `ppt/presentation.xml`, and several layout/master/theme/notes/comment lookups select relationships by conventional target-path prefixes. Valid OPC relationship targets outside those paths remain a coverage gap. The existing typed relationship reader can support a future correction; no correction is included in `xml-scan2`.

Classic comments currently use a generic nonempty-text collector, synthesize sequential IDs, and leave author, date and position empty. The [classic comment contract](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.comment?view=openxml-3.0.1) identifies comments by author plus index and defines `dt` as last modification time. ## Deferred artwork and on-demand node rendering

`deferred-artwork2` adds the `defer_artwork` parse option (`deferArtwork` in the WASM bridge). When it is set, the parser omits the generated shape, picture, chart and ink SVG together with its paint bounds and fallback pictures, and the three warnings only shape, picture and chart rendering can raise (`unsupported-shape-appearance`, `unsupported-picture-appearance` and `unsupported-chart-rendering`); geometry, fills, lines, text, tables, assets, editing metadata, source XML and every other warning are parsed as before. Ink content parts are still rendered, because whether the render succeeds decides between the ink and its saved preview inside markup-compatibility fallbacks; only their SVG is dropped once that choice is made, so `ink-fallback` is reported as before. `render_node_artwork`, exported to WASM as `render_presentation_node_artwork`, renders one node on demand: it parses the presentation again with artwork deferred for every node except the target, which is addressed by slide index, layout id or master id plus the node id stored in the model, including the `layout:` and `master:` prefixes of inherited decorative nodes. Materialized SmartArt children receive composite `frame:smartart:model` ids after their drawing is parsed, so they render whenever their frame's slide, layout or master is targeted and are addressed by the id the model gives them. Each call parses the whole presentation once without rendering; a retained parse state is needed before many nodes of one deck can be rendered cheaply.

A first candidate, `deferred-artwork1`, skipped the ink render as well and failed its semantic gate on 4 of 1,156 inputs, exactly those whose ink content parts sit inside `mc:AlternateContent`: without a preview the handler chose the saved-preview picture that the eager parse replaces with the ink node. Its receipts and `decision.json` (`superseded`) remain in its experiment directory; its first gate run also stopped at input 825 when the disk filled, and that partial receipt is kept beside the complete one. `deferred-artwork2` corrects the ink path. Its eager default is exact against `arena-dom1` on all 1,156 established outputs and errors, and its WASM bridge is exact on the 687-input cohort (625 compact models, 41,467 artwork hashes). The deferred mode's semantic gate, `artwork_deferral_gate.py`, passes on each of the 1,156 inputs: the eager and deferred compact models are identical once artwork fields and rendering-only warnings are removed, statuses and error texts agree, the deferred model holds no artwork, and up to 6 on-demand renders per input, 4,435 in all, equal the eagerly stored artwork (4,435 matched). All 401 workspace checks pass, including the deferred-artwork tests, with the one pre-existing ignored check unchanged, and the wasm32 workspace check compiles.

The deferred pilot (`deferred_timing.py`) interleaves the eager default, the deferred mode, Office Oxide and undoc on the fixed 40-input `expanded-xml-indexed` selection with seven warm samples each. The median paired ratio of eager to deferred time is 1.248× (1.207–1.414×), of Office Oxide to deferred time 0.490× (0.416–0.596×) and of Office Oxide to eager time 0.353× (0.305–0.434×); intervals are 95% bootstrap intervals. The deferred mode is faster than Office Oxide on 7 of the 40 inputs and the eager default on 5. Summed per-input medians are 1,008.560 ms eager, 349.976 ms deferred, 49.618 ms Office Oxide and 129.465 ms undoc. The sums are dominated by the one input above 100 ms (906.089 to 281.527 ms). The run shared the machine with unrelated user processes (load average 12.1–12.4 on 14 logical cores, against 24.6–25.1 during the `arena-dom1` pilot and 6.9–7.2 during `pattern-cache1`), so the comparison relies on paired interleaving; the median per-input sample coefficient of variation is 0.14, and 4 of the 40 inputs, none above 1.3 ms eager, measure slower in deferred mode although it does strictly less work. The deferred mode is a different workload with no generated artwork, so these figures are reported apart from the eager default and are tuning results on the fixed selection, not untouched validation. The build is retained; the published eight-parser comparison and README heatmaps still describe `editing-namespaces1`.
